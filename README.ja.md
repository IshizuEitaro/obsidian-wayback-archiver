[English](./README.md)

Wayback Archiver は、Obsidian ノート内の Web リンクを Wayback Machine などのアーカイブサービスへ自動保存し、アーカイブリンクを追記する Obsidian プラグインです。
Vault 全体のアーカイブ、柔軟なフィルタリング（対象指定・除外）、URL 置換ルール、失敗ログの再試行、プロフィール管理、代替プロバイダー（フォールバック）に対応しています。

## インストール

1. Obsidian の「コミュニティプラグイン」ブラウザから **Wayback Archiver** をインストールします。
2. Obsidian の設定でプラグインを有効化します。
3. プラグインの設定タブで必要な API キーを設定します（[グローバル API キー](#グローバル-api-キー)を参照）。

## コアコンセプト

### アーカイブ処理

プラグインは指定された対象（現在のノート、選択テキスト、または Vault 全体）をスキャンし、Markdown リンク（`[text](url)`、`![text](url)`）、HTML リンク（`<a href="url">text</a>`、`<img src="url">`）、およびプレーンテキスト URL（`https://example.com`）を検出します。
対象 URL ごとに Archive.org Wayback Machine の SPN (Save Page Now) API v2 を使用してスナップショットの保存を試みます。

### アーカイブリンク

アーカイブ保存に成功すると、元のリンクの直後に新しいアーカイブリンク（Markdown または HTML 形式）を挿入します。
リンクの表記形式は設定からカスタマイズできます。

**例**：
`[Example Site](https://example.com)` は以下のように変換されます。
`[Example Site](https://example.com) [(Archived on 2025-04-10)](https://web.archive.org/web/20250410...)`

元のリンクの直後にすでにアーカイブリンクが存在する場合、強制コマンド（「現在のノートのリンクを強制的に再アーカイブ」など）を使用するか、既存リンクが「アーカイブの鮮度 (Archive Freshness)」の閾値より古い場合を除き、重複リンクの追加を自動的にスキップします。

> [!NOTE]
> **隣接リンクの判定仕様**：既存のアーカイブリンクが元のリンクの直後 **300文字以内**（隣接検索制限）に存在する場合に「隣接」と判定します。
> これにより正規表現処理を最適化し、文書の下部にある無関係なアーカイブリンクとの誤判定を防ぎます。

### プロフィール

複数の設定プロフィールを作成して異なる構成を管理できます。
各プロフィールには個別のルール（フィルタリング、置換、API オプションなど）を保存できます。
Archive.org の API キーはすべてのプロフィールで共通（グローバル）して使用されます。
設定タブからいつでもプロフィールを切り替えられます。

### フィルタリング

複数のフィルタリング機構により、アーカイブ対象のリンクを詳細に制御できます。

- **除外するパターン (Ignore Patterns)**：このパターンに一致する URL は常にアーカイブをスキップします。
- **対象パターン (Include Patterns)**：アーカイブ対象となるノートやリンクを定義します（パス、単語、URL）。
- **パス / 単語パターン (Path/Word Patterns)**：**Vault 全体**を対象とするコマンド、および**選択範囲なしでノート全体を処理する現在のノートコマンド**に適用されます。ノートが処理されるには、パスパターンと単語パターンの*両方*（両方が定義されている場合）に一致する必要があります。テキスト選択状態でコマンドを実行した場合は選択範囲が優先され、パス / 単語パターンによるノート単位のフィルタリングは無視されます。
- **URL パターン**：**すべて**のコマンドに適用され、対象ノート内のリンクをフィルタリングします。

### 置換ルール

URL をアーカイブへ送信する前に、検索・置換ルールを適用できます。
URL の不備を補正したり、特定バージョンの Web サイトへリダイレクト（例：`reddit.com` -> `old.reddit.com`）したりする際に活用できます。

### アーカイブ失敗のログ

API エラー、タイムアウト、レート制限などでアーカイブに失敗した場合、その試行がログに記録されます。
失敗した項目は表示・エクスポート・再試行が可能です。

プラグインは内部データ領域に「失敗したアーカイブの内部リスト」を保持しています。
このリストは JSON または CSV 形式で外部ファイルへエクスポートできます。
プラグイン内の内部リストをクリアしても、エクスポート済みのログファイルは削除されません。
エクスポートされたログファイルは、失敗ログフォルダ（通常は `.obsidian/plugins/wayback-archiver/failed_logs/`）に保存されます。

ログの肥大化を防ぐため、同一の元 URL・ノート・ターゲット URL・処理段階で発生した失敗は、自動的に 1 つの失敗エントリに統合（Coalesce）されます。

## 安全な長時間アーカイブ

Vault 全体や複数ノートの処理を実行する前に、対象ノート数・処理対象のリンク数・ユニーク URL 数を事前確認ダイアログに表示します。
アーカイブ実行中は、ステータスバーに加えてコンパクトなフローティング進捗チップ（Progress Chip）が表示され、リアルタイムの進行状況を確認できます。進捗ダイアログでは各 URL の詳細状態が表示され、処理待ちの特定リンクを個別スキップ（Skip）できるほか、チップやステータスバーをクリックしていつでも再表示できます。進捗サマリーでは、完了数とともに保存成功数・失敗数・スキップ数（`skipped`）が動的に集計・表示されます。
キャンセル実行後は新しいアーカイブ処理を開始せず、それまでに完了したノートへの書き込みのみを保持します。
実行中だった通信がキャンセル後に完了した場合でも、その結果がノートへ後から書き込まれることはありません。

ベア URL (bare URL) の処理は設定から有効・無効を切り替えられます。
Markdown や HTML 内の画像 URL も引き続きアーカイブ対象に含まれます。
除外ドメイン (Ignored domains) は完全なホスト名境界で判定され、サブドメインを含めて対象から除外されます。
互換性の維持のため、従来の正規表現による URL パターン指定も引き続き利用可能です。
API のスロットル（レート制限）が発生した場合は、設定された間隔と回数に従って自動で再試行します。
キャプチャ失敗時のフォールバック処理では、「アーカイブの鮮度 (Archive freshness)」の設定期間内に存在する固定タイムスタンプのスナップショットのみを使用します。
鮮度設定が `0` の場合は、このフォールバック検索を行いません。

Archive.org の認証情報は、ユーザーが選択した SecretStorage または平文 `data.json` の保存方式を維持します。

Obsidian 1.13 以降では、設定の検索やインライン検証に対応した宣言的設定 (Declarative Settings) UI を使用します。
Obsidian 1.8.10–1.12 では、従来のレンダラーを引き続き使用して互換性を保ちます。
保存されている不正な数値データはプラグイン読み込み時に安全な範囲へ自動正規化され、プロフィールデータや認証情報の保存形式は既存のものをそのまま維持します。

## コンテキストメニュー操作

デスクトップ版およびモバイル版の Obsidian では、エディタ上、ファイルエクスプローラーの単一ノート、選択した URL、ならびに複数ノートの選択メニューから、通常アーカイブまたは強制 (force) アーカイブ操作を直接起動できます。

URL に対するコンテキストメニュー操作は、対象 URL のアーカイブ処理を一度だけ実行し、アクティブなノート内にある該当 URL のすべての箇所へ同じ結果を適用します。
これには Markdown のリンクや画像、HTML の `<a>` タグや `<img>` タグ、設定で有効化されたベア URL が含まれます。

複数ノート選択時の操作では、重複を除外した Markdown ノートのみを事前スキャンし、全体の進捗表示および共通のキャンセル処理を使用して安全に実行されます。

## コマンド

コマンドパレット（Ctrl/Cmd + P）から各種コマンドを実行できます。

### 現在のノートのリンクをアーカイブ (Archive links in current note)

- **対象**：現在アクティブなノート内のリンクを処理します。テキスト選択時は選択範囲内のリンクのみを処理します。
- **ロジック**：
    - **除外 URL パターン**と**対象 URL パターン**を適用します。
    - 隣接するアーカイブリンクが存在するリンクはスキップします（既存リンクが「アーカイブ鮮度」設定より古い場合を除く）。
    - SPN API を使用して対象リンクのアーカイブを試みます。
    - 成功した場合、アーカイブリンクを挿入または置換します。
    - 直近（「アーカイブ鮮度」の範囲内）のスナップショットが既に存在するかレート制限に達したことを API が示した場合、隣接アーカイブリンクが存在しない場合に限り、新規保存ではなく**保存済みの履歴から最新スナップショット URL（タイムスタンプ付き）を取得**して挿入を試みます。
- **注意**：パス / 単語パターンによるフィルタリングは、**テキスト選択をせずノート全体を処理する場合にのみ適用されます**。テキスト選択状態では選択範囲が優先され、パス / 単語パターンは無視されます。

### Vault内のすべてのリンクをアーカイブ (Archive all links in vault)

- **対象**：Vault 内のすべての Markdown ファイルに含まれるリンクを処理します。実行前に確認ダイアログが表示されます。
- **ロジック**：
    - **対象パスパターン**と**対象単語パターン**に基づきノートをフィルタリングします（両方定義されている場合は両方に一致が必要）。スキップされたファイルはログに記録されます。
    - 選択されたノート内のリンクを**除外 URL パターン**と**対象 URL パターン**でフィルタリングします。
    - 「現在のノートのリンクをアーカイブ」と同等のアーカイブ処理および挿入 / 置換ロジックを適用します。
- **注意**：Vault の規模やリンク数によっては処理に時間がかかる場合があります。

### 現在のノートのリンクを強制的に再アーカイブ (Force re-archive links in current note)

- **対象**：現在アクティブなノート内のリンクを処理します。テキスト選択時は選択範囲内のリンクのみを処理します。
- **ロジック**：
    - **除外 URL パターン**と**対象 URL パターン**を適用します。
    - 「アーカイブ鮮度」設定や既存のアーカイブリンクの有無を**無視**して、対象リンクのアーカイブを試みます。
    - 成功した場合、既存の隣接アーカイブリンクを**置換**するか、存在しない場合は新しく挿入します。
    - アーカイブ失敗時やレート制限到達時は、**リンクの挿入や置換を行いません**。既存のリンクは維持されます。
- **注意**：パス / 単語パターンによるフィルタリングは、**テキスト選択をせずノート全体を処理する場合にのみ適用されます**。テキスト選択状態では選択範囲が優先されます。

### Vault内のすべてのリンクを強制的に再アーカイブ (Force re-archive all links in vault)

- **対象**：Vault 内のすべての Markdown ファイルに含まれるリンクを処理します。実行前に確認ダイアログが表示されます。
- **ロジック**：
    - **対象パスパターン**と**対象単語パターン**に基づきノートをフィルタリングします。スキップされたファイルはログに記録されます。
    - 選択されたノート内のリンクを**除外 URL パターン**と**対象 URL パターン**でフィルタリングします。
    - 「現在のノートのリンクを強制的に再アーカイブ」と同等のアーカイブおよび置換ロジックを適用します。
- **注意**：処理に時間がかかる場合があります。

### 失敗したアーカイブを再試行 (Retry failed archive attempts)

- **アクション**：失敗ログフォルダ（通常 `.obsidian/plugins/wayback-archiver/failed_logs/`）から失敗ログファイル（`.json` または `.csv`）を選択します。
- **ロジック**：選択されたファイル内の各 URL のアーカイブを試みます。
- **成功時**：
    - ログファイルから該当エントリを削除し、**隣接アーカイブリンクがまだ存在しない場合に限り**、元のノートへアーカイブリンクを挿入します。
    - 全エントリが成功した場合、ログファイルは自動削除されます。
    - 「失敗ログの自動クリア」が無効な場合は、ログクリア前に確認ダイアログが表示されます。

### 失敗したアーカイブを再試行（強制置換） (Retry failed archive attempts (Force replace))

- **アクション**：標準の再試行と同様ですが、強制置換ロジックを使用します。
- **ロジック**：選択されたファイル内の各 URL のアーカイブを試みます。
- **成功時**：
    - ログファイルから該当エントリを削除し、元のノートにある既存の隣接アーカイブリンクを**強制置換**（存在しない場合は新規挿入）します。
    - 全エントリが成功した場合、ログファイルは自動削除されます。
    - 「失敗ログの自動クリア」が無効な場合は、ログクリア前に確認ダイアログが表示されます。

### 失敗したアーカイブのログをエクスポート (Export failed archive log)

- **アクション**：現在の失敗したアーカイブのリストをファイルへエクスポートします。
- **ロジック**：
    - CSV または JSON 形式を選択します。
    - 失敗ログフォルダ内にタイムスタンプ付きファイル（例：`wayback-archiver-failed-log-YYYYMMDDHHMMSS.json`）として保存します。
    - エクスポート成功後、内部の失敗ログリストをクリアするか確認ダイアログが表示されます。

### 失敗したアーカイブのログをクリア (Clear failed archive log)

- **アクション**：確認後、内部の失敗アーカイブ操作リストをクリアします。
- **注意**：エクスポート済みのログファイルは削除されません。

### archive.today および ウェブ魚拓の補助コマンド

代替プロバイダーとの直接連携や、バックグラウンド保留キューの手動管理を行うコマンド群です。

- **Submit current note links to archive.today (現在のノートのリンクを archive.today へ送信)**：
    - **対象**：アクティブノートのリンク。テキスト選択時は選択範囲内のみ。
    - **処理**：対象リンクの archive.today へのバックグラウンド送信を開始します。最終スナップショット URL が即座に得られない場合は保留キューに追加されます。
    - **注意**：archive.today の非公式送信フローに依存しているため、レート制限・CAPTCHA・ボット対策・仕様変更などにより失敗する可能性があります。
- **Insert latest archive.today snapshot in current note (現在のノートに最新の archive.today スナップショットを挿入)**：
    - **対象**：現在のノートのリンク。テキスト選択時は選択範囲内のみ。
    - **処理**：対象リンクの最新スナップショットを archive.today に問い合わせ、新規保存を行わずにアーカイブリンクを挿入します。
- **Insert latest Web Gyotaku snapshot in current note (現在のノートに最新のウェブ魚拓スナップショットを挿入)**：
    - **対象**：現在のノートのリンク。テキスト選択時は選択範囲内のみ。
    - **処理**：対象リンクの最新スナップショットをウェブ魚拓 (Megalodon.jp) に問い合わせ、新規保存を行わずにアーカイブリンクを挿入します。
- **Check pending archive.today snapshots now (保留中の archive.today スナップショットを今すぐ確認)**：
    - **処理**：保留中の archive.today バックグラウンド送信リクエストのステータス確認ポーリングを即時実行します。
- **Open next failed URLs in archive.today (失敗した次のURLを archive.today で開く)**：
    - **処理**：保存に失敗した URL のバッチを、デフォルトブラウザで archive.today の手動保存ページとして開きます。CAPTCHA 解除や手動保存に使用します。
- **Open next failed URLs in Web Gyotaku (失敗した次のURLをウェブ魚拓で開く)**：
    - **処理**：保存に失敗した URL のバッチを、デフォルトブラウザでウェブ魚拓 (Megalodon.jp) の手動保存ページとして開きます。
    - **注意**：ウェブ魚拓への自動送信は行われません。保存操作はブラウザ上で手動で行う必要があります。

## 設定ガイド

設定は、Obsidian の設定 -> コミュニティプラグイン -> Wayback Archiver からアクセスできます。

### グローバル API キー

Archive.org SPN API v2 の利用に必要なキーであり、全プロフィールで共有されます。

- **Archive.org SPN Access Key**：S3 形式のアクセスキーを入力します。
- **Archive.org SPN Secret Key**：S3 形式のシークレットキーを入力します。
- **キーの取得方法**：Archive.org にログインした状態で、アカウント設定ページ（[https://archive.org/account/s3.php](https://archive.org/account/s3.php)）から生成・取得できます。

### プロフィールの管理

設定セット（プロフィール）を管理します。

- **Active Profile**：現在アクティブで編集対象のプロフィールをドロップダウンから選択します。
- **Create Profile**：デフォルト設定を基に新しいプロフィールを作成して有効化します。
- **Rename Profile**：アクティブなプロフィールの名前を変更します（"default" プロフィールは変更不可）。
- **Delete Profile**：確認後、アクティブなプロフィールを削除します（"default" プロフィールは削除不可）。削除後は "default" プロフィールへ切り替わります。

### プロフィール設定

以下の設定は**現在アクティブなプロフィール**にのみ適用されます。

#### 一般設定 (General)

- **Date Format**：アーカイブリンク内の `{date}` プレースホルダーに使用する日付フォーマット。`date-fns` のトークン（例：`yyyy-MM-dd`、`dd MMM yyyy`）を使用します。デフォルト：`yyyy-MM-dd`。
- **Archive Link Text**：挿入されるアーカイブリンクのテンプレート。利用可能なプレースホルダー：
    - `{date}`：フォーマットされたアーカイブ日付に置換されます。
    - `{provider}`：アーカイブプロバイダー名（例：`Wayback Machine`、`archive.today`、`ウェブ魚拓 (Megalodon.jp)`）に置換されます。
    - **デフォルト**：`(Archived on {date})`。

#### フィルタリングルール (Filtering Rules)

- **Ignore URL Patterns**：スキップする URL パターンを 1 行に 1 つずつ入力します（テキストまたは正規表現）。デフォルトで `web.archive.org` は無視されます。
- **URL Patterns**：（全コマンド対象）このパターンのいずれかに一致する URL のみ処理します（1 行 1 パターン）。空欄の場合はすべての URL を処理します（Ignore URL Patterns が優先）。
- **Path Patterns**：（Vault 全体、および選択なしの現在ノート処理対象）ファイルパスがパターンに一致するノートのみ処理します（1 行 1 パターン）。空欄の場合はすべてのノートを処理します。
- **Word/Phrase Patterns**：（Vault 全体、および選択なしの現在ノート処理対象）指定した単語・フレーズを 1 つ以上含むノートのみ処理します。空欄の場合は全ノートを処理します。
- **適用ロジック**：対象コマンドにおいてパスパターンと単語パターンの両方が定義されている場合、ノートが処理されるには**両方**に一致する必要があります。その上で URL パターンによりノート内の各リンクがフィルタリングされます。

#### URL 置換ルール (URL Substitution Rules)

URL をアーカイブへ送信する前に検索・置換ルールを適用します。

- 「Add Substitution Rule」をクリックして行を追加します。
- **Find**：検索パターン（テキストまたは正規表現）を入力します。
- **Replace with**：置換後のテキストを入力します。一致箇所を削除する場合は空欄にします。
- **Regex?**：「Find」のパターンを正規表現として扱う場合にチェックを入れます（`g` フラグが自動適用されます）。
- **Remove**：置換ルールを削除します。
- ルールは表示順（上から順）に適用されます。

#### アーカイブプロバイダーとフォールバック (Archive Providers and Fallbacks)

Wayback Machine での保存失敗時や、URL ごとのポリシーに応じた代替ソースを設定します。

- **Use archive.today fallback**：Wayback Machine での保存失敗時に、既存の archive.today スナップショットを検索・解決して挿入します。単体では新規保存リクエストを送信しません。
- **Use Web Gyotaku fallback**：先行プロバイダーが失敗した際、既存のウェブ魚拓 (Megalodon.jp) スナップショットを解決して挿入します（解決のみ、自動保存非対応）。
- **Background archive.today auto-submit**：【実験的機能】デフォルト無効。有効時、Wayback Machine の保存失敗時にバックグラウンド HTTP リクエスト経由で archive.today へ保存リクエストを自動送信します。

#### archive.today 保留キューおよび手動フォールバックオプション (archive.today Pending Queue and Manual Fallback Options)

archive.today へのバックグラウンド送信・検証キューを微調整します。

- **archive.today submit delay between requests (ms)**：IP レート制限回避のための自動送信リクエスト間隔（ミリ秒）。範囲：1,000ms 〜 10,000ms。デフォルト：5,000ms。
- **archive.today pending poll interval (ms)**：保留中送信のステータス確認ポーリング間隔。範囲：15,000ms 〜 300,000ms。デフォルト：60,000ms。
- **archive.today pending poll batch size**：1 回のポーリングサイクルで確認する保留エントリ数。範囲：1 〜 10。デフォルト：3。
- **archive.today pending max wait (ms)**：保留送信がタイムアウトし失敗リストへ移動するまでの最大待ち時間。範囲：60,000ms 〜 1,200,000ms。デフォルト：600,000ms。
- **archive.today max pending count**：キューに同時保持できる保留アイテムの最大数。範囲：1 〜 100。デフォルト：30。
- **Manual save batch size**：手動フォールバックコマンド実行時に一度にブラウザタブで開く URL の最大数。範囲：1 〜 5。デフォルト：5。

#### URLごとのアーカイブポリシー (Per-URL Archive Policies)

ターゲット URL の正規表現パターンに基づき、使用プロバイダーをカスタマイズします。

- **フォーマット**：`パターン => プロバイダー` の形式で 1 行 1 ルールを入力します。
- **サポートされているプロバイダー**：
    - `wayback`: Archive.org Wayback Machine（保存および解決）
    - `archiveToday`: archive.today（既存スナップショットの解決のみ）
    - `archiveToday:auto`: archive.today（バックグラウンド自動送信と後刻の解決）
    - `megalodon`: ウェブ魚拓 (Megalodon.jp)（既存スナップショットの解決のみ）
- **設定例**：
    ```text
    ^https://x\.com/ => archiveToday:auto
    example\.com => wayback, archiveToday
    ```

#### 詳細設定 (Advanced Settings)

- **API Request Delay (ms)**：連続する API 呼び出し間の最小待機時間（ミリ秒）。レート制限（429 エラー）回避に有効です。デフォルト：`2000ms`。
- **Max Status Check Retries**：保留中ジョブのステータス確認最大回数。到達時はタイムアウト失敗として記録します。デフォルト：`3`。
- **Archive Freshness (Days)**：（標準アーカイブコマンド対象）隣接アーカイブリンクのタイムスタンプが指定日数以内であればスキップします。指定日数より古い場合や日付不明な場合は再アーカイブ・置換を試みます。`0` 設定時は既存リンクを古いものとして扱います。デフォルト：`0`。
- **Auto Clear Failed Logs**：有効時、再試行成功した失敗ログエントリを確認なしで自動削除します。デフォルト：`false`。

#### SPN API v2 オプション

Archive.org SPN API v2 のキャプチャプロセス設定を制御します。

- **Capture Screenshot**：スナップショットキャプチャ時にスクリーンショット画像を要求します（`capture_screenshot=1`）。デフォルト：`false`。
- **Capture All Resources (capture_all=1)**：CSS・JS などの埋め込みリソースをより多く取得します（`capture_all=1`）。デフォルト：`false`。
- **JS Behavior Timeout (ms)**：キャプチャ中の JavaScript 実行最大許可時間（ミリ秒）。`0` 指定で API デフォルト値が使用されます。デフォルト：`0`。
- **Force GET Request (force_get=1)**：HTTP GET リクエストの使用を強制します（`force_get=1`）。デフォルト：`false`。
- **Capture Outlinks (capture_outlinks=1)**：対象 URL からリンクされている外部ページもキャプチャを試みます（`capture_outlinks=1`）。デフォルト：`false`。

## トラブルシューティング FAQ

**Q**：API キーが機能しない、または「Configuration Error」と表示されます。

**A**：
1. [https://archive.org/account/s3.php](https://archive.org/account/s3.php) からコピーした **Access Key** と **Secret Key** が「Global API Keys」セクションに正確に入力されているか確認してください。
2. 前後に余分な空白文字が入っていないか確認してください。
3. これらはグローバル設定であり、プロフィールごとに個別に設定する必要はありません。

**Q**：アーカイブが頻繁に失敗する、またはレート制限エラー（HTTP 429）が発生します。

**A**：
1. 詳細設定の **API Request Delay** を引き上げてください（例：`3000ms` または `5000ms`）。
2. Archive.org の 1 日のキャプチャ上限に達している可能性があります。429 エラー検出時、プラグインは利用可能な最新スナップショット URL の取得を試みます。
3. エクスポートコマンドや再試行コマンドを使用して、**Failed Archive Log** のエラー詳細を確認してください。

**Q**：特定のリンクがアーカイブされません。

**A**：以下の点を確認してください。
1. **除外パターン (Ignore Patterns)**：アクティブプロフィールの Ignore URL Patterns に該当していませんか？
2. **対象パターン (Include Patterns)**：
    - （Vault 全体、または選択なしの現在ノート処理）ノートのパスが Path Patterns に一致していますか？
    - （Vault 全体、または選択なしの現在ノート処理）ノートの内容が Word/Phrase Patterns に一致していますか？
    - （全コマンド）リンクの URL が URL Patterns に一致していますか？
3. **隣接アーカイブリンク**：元のリンクの直後にすでにアーカイブリンクが存在していませんか？標準コマンドは「Archive Freshness」より新しければスキップします。強制再アーカイブコマンドであれば処理を実行できます。
4. **非 HTTP(S) スキーム**：`http://` および `https://` リンクのみが対象です。`ftp://` や `mailto:` などは無視されます。
5. **API エラー**：Archive.org 側で保存に失敗している可能性があります。「Failed Archive Log」を確認してください。

**Q**：強制再アーカイブコマンドを使用しましたが、古いアーカイブリンクが置換されませんでした。

**A**：強制再アーカイブコマンドは、**新しくリクエストしたアーカイブ保存に成功した場合にのみ**既存のリンクを置換します。保存失敗時やレート制限到達時は、ノートの内容は書き換えられず古いリンクが維持されます。

**Q**：アーカイブに毎回失敗するリンクはどう管理すればよいですか？

**A**：
1. **失敗したアーカイブのログをエクスポート** コマンドで失敗 URL とエラー一覧を出力します。
2. 失敗原因を調査します（Web サイトによるクローラーブロック、一時的な障害など）。
3. 定期的に **失敗したアーカイブを再試行** コマンドを実行します。
4. 保存不可能な URL は「Ignore URL Patterns」への登録をご検討ください。
5. 追跡を停止する場合は **失敗したアーカイブのログをクリア** コマンドでリストから削除できます。

**Q**：置換ルール (Substitution Rules) がうまく機能しません。

**A**：
1. 正規表現使用時は **Regex?** にチェックが入っているか確認してください。
2. ルールの順序を確認してください（上から順に適用されます）。
3. 「Find」パターンが置換対象の URL 部分に正確に一致しているか確認してください（通常一致は大文字小文字を区別します）。

**Q**：現在のノートをアーカイブする際、パスパターンや単語パターンによるフィルタリングはどう適用されますか？

**A**：パスパターンと単語パターンは、**テキスト選択をせずにノート全体を処理する場合**に適用されます。ノートがこれらのパターンに一致しない場合、アーカイブ処理はスキップされます。
一方、**テキストを選択した状態でコマンドを実行した場合**は選択範囲の処理が優先されるため、ノート単位のフィルタリングは無視されます。なお URL パターンによるリンク単位のフィルタリングは選択の有無に関わらず機能します。

**Q**：archive.today 自動送信でスナップショットが作成されません。

**A**：archive.today 自動送信は実験的なベストエフォート機能です。公式 API が存在しないため、レート制限・CAPTCHA・ボット対策・仕様変更などによりブロックされる場合があります。**Open next failed URLs in archive.today** コマンドでブラウザから手動保存し、その後 **Check pending archive.today snapshots now** または **Insert latest archive.today snapshot in current note** を実行してください。

### アーカイブプロバイダーへの支援

- **archive.today**：[archive.today / archive.md](https://archive.md/) のトップページに記載されている Monero アドレスから寄付が可能です。
- **ウェブ魚拓 (Megalodon.jp)**：インフラ支援につながる有料プレミアムサービスを提供しています。詳細は [ウェブ魚拓 利用規約・仕様紹介](https://megalodon.jp/pc/user/introduction) をご覧ください。

## 制限事項

- **Wayback Machine**：キャプチャ保存の失敗・タイムアウト・レート制限が発生する可能性があります。保存制限到達時は、新規保存の代わりに利用可能な最新の既存スナップショットの挿入を試みる場合があります。
- **archive.today**：既存スナップショットの解決と実験的自動送信に対応しています。ただし公式 API が存在しないため、自動送信機能はベストエフォートであり予告なく動作しなくなる可能性があります。
- **ウェブ魚拓 (Megalodon.jp)**：既存スナップショットの解決（検索）のみをサポートしています。新規 URL の自動保存・送信機能はありません。
- **隣接アーカイブの判定仕様**：既存アーカイブリンクは、元のリンク直後の隣接検索制限文字数の範囲内でのみ検出されます。
- **URL の重複**：同一 URL がノート内に複数存在する場合、スキャン時に検出された元の位置に最も近いものを処理します。

### 【実験的機能】archive.today 自動送信 (auto-submit)

`archive.today 自動送信` は実験的なフォールバック機能です。有効時、Wayback Machine での保存失敗時に自動で archive.today へ保存リクエストを送信します。

安定した公開 API が提供されていないため、本機能はベストエフォートで提供されます。以下の要因により送信失敗や不安定な動作が発生する可能性があります。

- archive.today 側の Web サイト仕様変更
- IP レート制限やボット排除（CAPTCHA 等）
- 地域やネットワーク環境による接続性の違い
- スナップショット生成の遅延（保留キューでの待機）

本オプションはデフォルトで無効です。より確実な保存を行いたい場合は、手動の archive.today保存コマンドの使用を推奨します。

> [!WARNING]
> 本機能はベストエフォートであり、予告なく機能しなくなる可能性があります。スナップショットの作成や最終 URL の取得は保証されません。
